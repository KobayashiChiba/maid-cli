# ⑥ 收敛式补漏

`build.py` 跑完通常还剩几十格（站位不对 / 材料当时没在手 / 附着面还没铺好）。
这个工具**每轮全量核验一遍，然后只去修不一致的格**，一轮轮收敛。

为什么不单格重试：她放不上的格子往往换个站位、补上材料就成 —— 整轮重来比原地重试有效。

## 前置
- 已跑过 `04-build-runner`
- 材料还在她背包里（或箱子里能取到）

## 用法
```bash
python repair.py --plan plan/house.json --maid A1B2C3 --rounds 6
```

## 参数
| 参数 | 默认 | 说明 |
|---|---|---|
| `--plan` | 必填 | 计划 JSON |
| `--maid` | `MAIDCLI_MAID` | 她的 6 位标签 |
| `--rounds` | 6 | 最多几轮 |
| `--interval` | 2 | 放置间隔（tick）|

## 输出
```
[round 1] 一致 942 · 不一致 92
[round 1] 修完：成功 64 / 待修 92
[round 2] 一致 1033 · 不一致 1
这轮没有进展，停止。残留清单见下：
  (-181,145,40)  蓝图=minecraft:purple_wool  →  实际=minecraft:air
```
退出码：`0` 收敛到零差异 · `1` 有残留 · `2` 参数/连接错误。

## 限制
- 有些格子**注定放不上**（例如屋顶最高点周围没有可站落点）—— 会稳定停在这几格，属正常
- 每轮耗时 ≈ `verify` 的耗时 + 修格子的时间
