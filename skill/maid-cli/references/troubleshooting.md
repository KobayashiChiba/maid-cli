# 排错手册（症状 → 原因 → 处置）

## 快速定位

```bash
maidcli ping                    # 通不通？
maidcli maids                   # 她在不在？
maidcli wake maid=<tag>         # 唤醒
maidcli sense state             # 卡在哪一步？queue 里是什么
maidcli sense self              # 位置对不对
```

---

## 症状对照表

| 症状 | 原因 | 处置 |
|---|---|---|
| `not_awake` | 没唤醒 / 300 秒超时释放了 | `wake maid=<tag>`，重发指令 |
| `not_found` | 标签写错 / 她没加载 | `maids` 看真实标签；未加载的先 `wake` |
| `too_far` | 离目标太远（该指令不自动走位）| 先 `go` 靠近；会话类要贴近到 8 格内 |
| `bad_state` | 前置状态不对（如界面没开）| 看提示；界面类先 `open`，或 `stop` 清理后重来 |
| `bad_arg` | 参数格式/范围不对 | 看 `hint`；坐标 `x,y,z`；负数写进等号 |
| `unauthorized` | key 失效（服务端重启）| `maidcli login <玩家名>`（CLI 会自动重试一次）|
| `unreachable` | 连不上服务端 | 服务端起没起？端口对不对？远程先建隧道 |
| `timeout` | 作业卡住 | `sense state` 看她卡在哪；`stop` 打断 |
| `unknown_cmd` | 指令名拼错 | `maidcli help` 列表 |
| 版本不一致警告 | CLI 与 mod 版本不同 | 换成同一版本的一套 |

## 五个高频疑难

### 1. 她走不动，`go` 一直超时，连 `tp` 都传不走
**原因**：她坐在船/矿车里（位置由载具决定，传送对乘客无效）。
**判据**：`data get entity <她> Pos` 与附近船的 `Pos` 完全重合。
**处置**：`maidcli macro dismount` —— 立刻落地，走位恢复。

### 2. 屋里高处的方块怎么都放不上
**原因**：屋内没有可站立的高处，`place` 找不到离目标 7 格内的落脚点。
**判据**：`failures[].reason` 是 `走位后仍够不到目标`。
**处置**：换个思路 —— 先搭临时脚手架，或接受这一格（屋顶最高点那类格子经常无解）。

### 3. 开完箱下一条指令就 `bad_state`
**原因**：界面还开着，绝大多数指令不允许在界面打开时执行。
**处置**：每个 `open` 配一个 `close`；慌乱时 `stop` 一把清（会连会话一起关，余料退回背包）。

### 4. 挖了方块但背包数量没变
**原因**：多半是掉的东西不是你以为的那个（`stone` 掉 `cobblestone`），或者 `drops=ground` 留在地上了。
**处置**：`sense inventory` 逐格看；`expect=` 用错会导致整批跳过。

### 5. `射不中：按配置的速度算，这个距离/高度打不到`
**原因**：弹道解算扫完所有仰角后，最小误差仍超过 2 格 —— 通常是有方块让所有抛物线提前"撞停"。
**判据**：服务端日志 `[MaidCLI] 弹道无解 from=… target=… bestErr=… bestPitch=…`
**处置**：换站位/换高度/换个靶；这是"宁可不射也不赌一发"的设计意图。

## 服务端日志里的关键词

| 日志 | 含义 |
|---|---|
| `[MaidCLI] 落脚点决策 target=… 选中=… 距目标=…` | 自动走位选了哪个站立点 |
| `[MaidCLI] 弹道无解 …` | 射箭解不出弹道（附现场数据）|
| `[MaidCLI] wake：… 已唤醒（加载 N / 实体tick M 圈）` | 唤醒成功并确认在 tick |
| `[MaidCLI] 跨会话清理：… 退回背包` | 崩溃/重启后自动退还残留物品 |
